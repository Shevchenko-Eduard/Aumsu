## 2. Принципы миграции

1. Контент не переносится автоматически «как есть»: сначала аудит и решение по каждой странице.
2. Один канонический URL на сущность; старые URL — 301.
3. Архив не попадает в основное меню и поиск.
4. Sveden сохраняет URL и microdata.
5. Документы дедуплицируются и получают метаданные.
6. Новости получают чистые URL и категории.
7. После запуска — мониторинг 404 и исправление редиректов.

## 3. Классификация контента

Для каждого URL заполняется решение:

| Решение | Что делать |
|---|---|
| keep | Оставить контент, обновить шаблон и URL при необходимости |
| merge | Объединить с канонической страницей, 301 |
| rewrite | Переписать устаревший/неверный контент |
| archive | Перенести в `/archive/*`, `noindex`, убрать из меню |
| redirect | 301 на близкую страницу |
| delete | 410 или удалить без замены |
| review | Ручная классификация |

Черновая карта: `specs/redirects/url-map.csv`. Её нужно пройти редакторами по разделам, отметив владельца и дату проверки.

## 4. Аудит по разделам

### 4.1 Университет

- Создать реальные страницы «О вузе», «История», «Миссия», «Стратегия», «Ректор», «Учёный совет».
- Не использовать `/sveden` как «Об университете».
- Структуру собрать один раз: факультеты, институты, колледжи, кафедры, управления, филиалы.
- У каждой кафедры/факультета — одна карточка, сотрудники, программы, документы, контакты.
- Телефонный справочник — в контактах, не отдельным разделом.

### 4.2 Поступление

- Один хаб `/admissions`.
- Уровни: бакалавриат/специалитет, магистратура, аспирантура, СПО, ДПО, иностранцы.
- Убрать старые стоимости 2012/2017, заменить текущими.
- Правила, сроки, экзамены, минимальные баллы, стоимость, общежитие, целевое — отдельные страницы.
- Подача документов — внешний ЛК + инструкция.
- Старые кампании — в архив.

### 4.3 Образование

- Каталог программ — единый; фильтры по уровню, факультету, форме.
- Карточка программы: код, название, уровень, профиль, форма, срок, бюджет/платно, документы, экзамены.
- Учебный процесс: расписание, учебные планы, методички.
- Библиотека — один раздел с подстраницами.
- ДПО и юридическая клиника — подразделы образования.
- Заочное обучение — `/education/distance`, без даты в URL.

### 4.4 Наука

- Направления, лаборатории, НИИ, технопарк.
- Аспирантура и диссоветы: текущие + архив дел.
- Конференции/гранты: текущие + архив по годам.
- Журналы: карточки, выпуски, правила, редколлегия, этика.
- Старые конференции 2010–2017 — архив.

### 4.5 Студенческая жизнь

- События, культура, спорт, организации, общежитие, стипендии, поддержка, ОВЗ, карьера.
- Музей: экспонаты, фото, видео; фотоархив — архив.
- Убрать диссертации из фотогазеты музея (сейчас там чужие страницы).
- Новости — в `/news`, а не в разделе.

### 4.6 Международное

- Иностранным студентам, партнёры, программы, мобильность, центр.
- Согласовать с управлением международной деятельности.

### 4.7 Новости

- Экспорт K2: заголовок, дата, автор, категория, текст, изображения.
- Новый URL `/news/YYYY/MM/slug`.
- Категории и теги.
- Архив по годам.
- Старые новости не удалять без проверки ссылок.

### 4.8 Документы

- Дедупликация по SHA-256.
- Метаданные: название, тип, раздел, подразделение, программа, дата, версия.
- Старые версии сохраняются, но не показываются по умолчанию.
- Sveden-документы — отдельный признак `isMandatory` и `svedenItemprop`.
- Битая ссылка на PDF — ошибка миграции.

### 4.9 Sveden

- Сохранить URL, поля, таблицы, microdata.
- Проверить обязательные `itemprop` и `itemtype`.
- Согласовать с ответственным за раскрытие информации и юристом.
- Не менять структуру без нормативного основания.

## 5. План миграции

### Этап 1. Инвентаризация и аудит (2–3 недели)

- Зафиксировать текущие URL и трафик.
- Назначить владельцев разделов.
- Пройти `url-map.csv`, утвердить keep/merge/archive/delete.
- Собрать список документов и новостей для переноса.
- Определить MVP-контент.

### Этап 2. Контент-контракт и каркас (2–3 недели)

- Утвердить `schemas/content.ts` и структуру JSON.
- Написать скрипты конвертации текущих HTML/данных в JSON.
- Подготовить mock-данные для всех типов страниц.
- Собрать Nuxt-каркас, PrimeVue-тему, навигацию, i18n.
- Настроить валидацию JSON и SSG.

### Этап 3. Контент и страницы (4–6 недель)

- Реализовать все шаблоны страниц.
- Подключить статические JSON, сконвертированные из текущих данных.
- Собрать каталог программ, новости, сотрудников, документы.
- Подготовить EN-переводы и EN-зеркало.
- Подготовить SVG-логотип в цветной и монохромной версиях.
- Проверить sveden-разметку.

### Этап 4. Редиректы и SEO (1–2 недели)

- Сгенерировать `redirects.json`/`gone.json` из `url-map.csv`.
- Проверить цепочки и целевые URL.
- Сделать sitemap/robots для RU/EN.
- Проверить canonical, meta, JSON-LD, hreflang.
- Передать `redirects.json` инфраструктурной команде.
- Настроить Search Console/Яндекс.Вебмастер (вне frontend).

### Этап 5. Запуск (1 неделя)

- Staging → приёмка → production.
- Передача `redirects.json`/`gone.json` и `nginx.conf`/`map` инфраструктуре.
- Smoke-тесты статики.
- Мониторинг 404/500 (на Nginx).
- Rollback-план (предыдущая статическая сборка).

### Этап 6. Стабилизация (2–4 недели)

- Исправить топ-404.
- Собрать обратную связь.
- Проверить веб-виталс.
- Донастроить поиск.
- Завершить архив.

## 6. Чек-лист запуска

- [ ] Все пункты меню ведут на 200.
- [ ] Нет 404 в шапке/футере.
- [ ] Все старые URL из топ-100 по трафику отдают 301.
- [ ] Sitemap валиден.
- [ ] Robots не закрывает sveden.
- [ ] Sveden microdata валидны.
- [ ] Формы работают, согласия на ПДн есть.
- [ ] Поиск находит страницы, новости, программы, сотрудников, документы.
- [ ] Мобильная версия проверена.
- [ ] Доступность проверена.
- [ ] Аналитика и события работают.
- [ ] Резервные копии и мониторинг настроены.
- [ ] Rollback возможен.
