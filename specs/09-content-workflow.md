# 09. Content workflow (static JSON)

## 1. Принципы

- Админки и CMS нет. Контент редактируется в JSON/файлах и попадает в репозиторий через Git.
- Frontend отвечает за схему, валидацию, сборку и отображение, но не за наполнение.
- Любое изменение проходит ревью и CI.
- Публикация = коммит в основную ветку + успешная сборка + деплой.
- Черновики не должны попадать в основную ветку/сборку.

## 2. Роли

| Роль | Ответственность |
|---|---|
| Поставщик контента | Даёт исходные тексты/файлы и проверяет факты |
| Контент-ревьюер | Проверяет факты, ссылки, даты, орфографию |
| Frontend-разработчик | Конвертирует данные в JSON, поддерживает схему, валидацию и компоненты |
| Frontend/переводчик | Готовит EN-версию: машинный перевод + выборочная проверка |
| Ответственный за sveden | Проверяет обязательные поля и microdata |
| Техлид | Ревью кода и сборки |

## 3. Конвертация текущего контента

- Источник: `Reference/`, `СборДанных/data/extracted/`, `pages.jsonl`, текущие HTML-страницы.
- Frontend пишет скрипты конвертации по типам сущностей.
- Результат — JSON по `schemas/content.ts`.
- Спорные записи помечаются `review` и не публикуются до проверки.
- Конвертация воспроизводима: скрипты в репозитории, входные данные фиксированы.
- После конвертации — ручная проверка ключевых страниц (главная, поступление, структура, sveden).
- EN-версия: машинный перевод + выборочная проверка силами frontend, глоссарий терминов. Внешней редактуры нет.

## 4. Формат

- Структура: `content/ru/...`, `content/en/...`, `content/shared/...` (см. `04-data-contract.md`).
- Формат JSON не согласован; контракт — `schemas/content.ts` + Zod. Поставщики контента адаптируют данные под него.
- Один файл — одна сущность.
- Поля — по `schemas/content.ts`.
- Никакого произвольного HTML, кроме разрешённых блоков.
- Медиа — в `public/media/`, пути относительные.
- Даты — ISO 8601.
- Телефоны — единый формат.

## 5. Жизненный цикл

```
идея → контент в JSON → ревью → PR → CI (validate/build) → merge → deploy
```

Требования:

- PR содержит только контент или только код, не смешивать без необходимости.
- CI проверяет JSON, ссылки, медиа, i18n, sveden.
- После merge автоматическая сборка и деплой на Nginx.
- Для срочных правок — тот же процесс, но с ускоренным ревью.
- Откат — revert коммита/предыдущая сборка.

## 6. Валидация

`npm run validate:content`:

- JSON соответствует Zod-схеме.
- Обязательные поля заполнены.
- Slug уникален и соответствует правилам.
- Внутренние ссылки существуют.
- Медиафайлы существуют; alt заполнен.
- RU/EN-пары согласованы.
- Sveden: обязательные `itemprop` присутствуют.
- Redirects: нет цепочек, `to` существует.
- Нет битых внешних ссылок (по списку).

Сборка не начинается, если валидация не прошла.

## 7. Sveden

- Данные приходят от ответственного за раскрытие информации.
- Формат — `SvedenPage`/`SvedenData`.
- Нельзя удалять обязательные поля и `itemprop`.
- Изменения проходят отдельное ревью.
- URL не меняются.
- Frontend-шаблон не должен ломать microdata.
- Перед релизом — проверка валидатором и вручную.

## 8. Переводы

- EN — полное зеркало, переводы готовит frontend.
- Для каждой RU-сущности — EN-файл или явная пометка «нет перевода».
- Непереведённые страницы не публикуются в EN-навигации.
- `translationOf`/`id` связывают пары.
- Тексты интерфейса — в `i18n/*.json`.
- При изменении RU-контента frontend обновляет EN; до перевода EN-страница может показывать предыдущую версию или быть скрыта (решение фиксируется).
- Глоссарий терминов и названий подразделений обязателен.

## 9. Медиа

- Форматы: JPEG, PNG, WebP, AVIF, SVG (санитайзен), PDF, DOC/DOCX, XLS/XLSX, PPT/PPTX.
- Логотип: SVG, цветная и монохромная версии, прозрачный фон.
- Изображения ≤ 5 МБ, документы ≤ 50 МБ.
- Имена: `YYYY-MM-DD-slug.ext`.
- Alt обязателен.
- Дедупликация по хешу — на стороне поставщика/скрипта.
- Frontend оптимизирует изображения при сборке (Nuxt Image или аналог).

## 10. Редиректы

- Источник: `specs/redirects/url-map.csv`.
- Frontend генерирует `public/redirects.json` и `gone.json`.
- CI проверяет формат и цепочки.
- Nginx применяет редиректы из `nginx.conf`/`map`.
- Изменения редиректов — через PR.

## 11. Навигация

- `content/ru/navigation.json`, `content/en/navigation.json`.
- Все пути существуют.
- Порядок и видимость — в JSON.
- Внешние ссылки — `external: true`.
- Не добавлять в меню архив и устаревшие страницы.

## 12. Качество текста

- Заголовки без CAPS LOCK.
- Даты с годом.
- Телефоны в едином формате.
- Ссылки осмысленные.
- Сокращения расшифрованы.
- Устаревшие страницы помечены «Архив» и датой.
- Нет «актуально на» без даты.

## 13. Релизный чек-лист

- [ ] `nuxt generate` проходит.
- [ ] Pagefind-индекс собран.
- [ ] `redirects.json`/`gone.json` обновлены.
- [ ] sitemap/robots обновлены.
- [ ] EN-страницы не сломаны.
- [ ] Sveden microdata проверены.
- [ ] Нет битых ссылок.
- [ ] Нет 404 в меню.
- [ ] Lighthouse/axe в норме.
- [ ] Деплой на staging и проверка.
